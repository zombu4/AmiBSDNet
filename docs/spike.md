# Feasibility spike: NetBSD rump networking on AmigaOS 3.2+ (PiStorm/Emu68)

Date: 2026-10-09. Native Windows build only (no containers or VMs).

## Result: GO

The NetBSD 11 rump kernel base, the socket layer, interfaces, routing,
IPv4 and IPv6 all compile for m68k and link into an AmigaOS hunk executable
with **zero unresolved symbols**. The only stubs are the 62 `rumpuser_*`
hypercalls, which are what we implement on Exec.

| Build | text | data | bss | total |
|---|---|---|---|---|
| `-O2 -DDIAGNOSTIC` | 1,442,538 | 41,512 | 77,800 | **1.56 MB** |
| `-Os -ffunction-sections -fdata-sections` | 610,058 | 37,282 | 72,084 | **720 KB** |

At 720 KB it fits comfortably even outside a PiStorm. That's before
trimming unused pieces such as the compat code (`RUMP_NBCOMPAT`).

## Toolchain (all native Windows, all inside this folder)

- `toolchain/`: Bartman's m68k-amiga-elf GCC 15.1 + binutils,
  extracted from `downloads/amiga-debug-1.8.2.vsix` (VS Code not needed).
- `netbsd-src/`: sparse clone of `github.com/NetBSD/src` branch `netbsd-11`
  (~180 MB). `core.protectNTFS=false` is set because the full tree has files
  named `aux`, which Windows reserves. Those files are outside the sparse set
  and never get written.
- `tools/build.py`: reads SRCS/.PATH straight from NetBSD's makefiles (no
  bmake or build.sh), compiles, does the `rumpns_` symbol rename, and
  builds `build/lib{rumpkern,rumpnet,rumpnet_net}.a`.
- `tools/link_test.sh`: the link test (no-op hypercall stubs).

```sh
python -I tools/build.py                                    # -O2 -DDIAGNOSTIC
RUMP_OPT="-Os -ffunction-sections -fdata-sections" python -I tools/build.py
```

## Problems found and how they were solved

1. **Int types:** this GCC defines 32-bit types as `long` (Amiga convention).
   NetBSD/m68k uses `int`. Fixed by overriding `__INT32_TYPE__` and related
   macros (same ABI). Host-side code keeps the Amiga definitions.
2. **No libgcc in the toolchain:** we use NetBSD's own C 64-bit arithmetic
   helpers (`common/lib/libc/quad`).
3. **Atomics:** NetBSD/m68k's versions are assembly. `src/kern/atomic_m68k.c`
   implements them with GCC `__atomic` builtins (CAS, 68020+). Memory barriers
   are compiler-only, because Emu68 runs the emulated CPU on one core. There
   are no 64-bit atomics, and NetBSD/m68k doesn't have them either.
4. **config(1) output:** the small `ioconf.c`/`ioconf.h` and `vers.c` are
   hand-written and generated by `build.py`.
5. **Link sets:** built with `-DRUMP_USE_CTOR` (components register through
   constructors). The remaining `link_set_*` sections (domains, sysctl,
   evcnts) get `__start_`/`__stop_` symbols from GNU ld automatically, and
   `elf2hunk` accepts the result. **This still has to be verified at run time.**
6. **Entry point:** `_start` is placed in `.text.unlikely.0_start` so it lands
   at offset 0 of the first hunk, where AmigaOS starts executing.
7. **TLS:** avoided with `RUMP_CURLWP_HYPERCALL`, so the current thread is
   looked up through a hypercall that `tc_UserData` can back.

## Not proven yet (next steps)

- That it actually **runs**. This needs a real `rumpuser` on Exec (tasks,
  SignalSemaphores, timer.device, AllocVec) and a test boot.
- Run-time check of the link sets and constructor ordering.
- SANA-II interface driver (modelled on rump's `libvirtif`).
- `bsdsocket.library` front end.

## Update: first boot (same day)

The kernel now boots under AmigaOS, and TCP over `lo0` works
(`src/test/rumptest.c`, about 9 s from emulator start to PASS). Problems
found getting there:

8. **The bundled `elf2hunk` corrupts PC-relative branches.** It emits
   HUNK_RELOC32 entries for `R_68K_PC32` relocations (cross-object `bra.l`
   tail calls), so LoadSeg adds the load address to a displacement. It is
   replaced by `tools/elf2hunk.py`, which puts every section into one hunk
   (so PC-relative references stay valid), relocates only `R_68K_32`, and
   flags the hunk `MEMF_FAST`.
9. **Alignment:** the m68k ABI aligns 32-bit types to 2 bytes, but NetBSD
   asserts natural alignment for atomically accessed pointers. The kernel
   side is built with `-malign-int`. Host code keeps the AmigaOS ABI, and
   the hypercall interface only passes 32-bit scalars and pointers.
10. **DOS requesters:** `GetVar()` with no `ENV:` assign raised "Please
    insert volume ENV". Rump threads now run with `pr_WindowPtr = -1`.
11. **Privacy:** `__FILE__` embedded absolute build paths, and therefore
    user names, in binaries. All builds use `-ffile-prefix-map`.

Debugging aids: `src/host/crashtrap.c` (a `tc_TrapCode` handler that
reports the faulting PC and a stack scan in ELF addresses), the
`amiga_rump_debug` levels in `rumpuser_amiga.c`, and `tools/winshot.ps1`,
which captures only the WinUAE window.
